# ICEIU · 学堂在线学习控制台

一个 Web 控制台，根据你提供的答案自动提交学堂在线（xuetangx.com）的小节/章节测试。
也支持查询与完成指定视频的观看进度，并回查服务器确认结果。
纯https协议实现。

## ✨ 功能

- 🔐 **只需一个 cookie**：粘贴登录态即可，纯 HTTPS 调用。
- 📊 **作业状态板**：一览所有作业的完成 / 判对情况。
- ⚡ **一键自动提交**：自动跳过已做的题，配速提交，避开服务器限速。
- 📜 **实时日志**：每道题提交结果逐行滚动，进度条 + 实时速率。
- 🎬 **整门课程视频**：选择一门已选课程，自动遍历该课程全部视频，跳过已完成项，批量上报并逐项回查；支持停止和重新运行。
- 📚 **课程答案库 Demo**：自动发现指定课程的作业、章节测试等练习，按题保存标准答案到本地 JSON，支持查看、下载和断点续采。
- 📄 **图文标记看完**：选择一门课程，一键标记全部图文（默认 3 并发），跳过已完成项并逐项回查。
- 💬 **讨论题批量完成**：在选定课程的未完成讨论单元逐条发布“1”，核对进度，并避免重复发帖。

## 🚀 快速开始

```bash
cd xuetangx
npm install                  # 安装后端依赖
cp .env.example .env         # 配置课程参数（见下）
npm run console              # 构建前端 + 启动服务（首次）
# 之后可直接 npm run serve（前端已构建）
```

浏览器打开 **http://127.0.0.1:8788**

1. F12 → Network → 复制任意请求的 Cookie 头（须含 `sessionid`、`csrftoken`），粘贴到「登录态」框 → 连接。
2. 把你的答案放入 `data/answers/`（格式见下）。
3. 点右上角「作业状态板」查看完成情况。
4. 点「开始」，看日志实时滚动。

视频功能独立于答案文件和 `.env` 中的作业课程参数：连接 Cookie 后，从下拉框选择一门「正在上课」的已选课程，点击「一键完成本课程全部视频」，即可自动扫描并执行，无需逐个粘贴链接。也可以先点击「查看本课程视频」查看数量。批量范围仅为选定课程的点播视频；不会处理其他课程、作业、考试或讨论。重跑会重新读取后端状态并跳过已完成视频。失败视频会单独列出；登录态失效会停止剩余批次。

视频默认 3 并发，可选并发数 1–3；每个视频内部的事件仍按顺序上报。所有视频请求统一配速，至少间隔 750 毫秒；已完成视频优先依据课程进度汇总跳过，减少重复查询。遇到 HTTP 429 时，所有任务共享等待时间，按 `Retry-After` 或平台提示自动重试，最多重试 3 次；仍被限速则停止剩余任务。HTTP 403 访问限制会停止任务，网络中断等无法确定写入结果的错误不会自动重放。

如只需指定一个视频，展开「指定单个视频」，粘贴学习页链接，查询后执行。链接格式为 `https://www.xuetangx.com/learn/space/<SIGN>/<课程标识>/<CLASSROOM_ID>/video/<LEAF_ID>`。

视频时长自动从后端进度、视频详情或播放地址接口读取；若均未返回，填写播放器显示的总秒数（例如 11:34 填 `694`）。每批最多 50 条记录；发送进度到 100% 后还会回查 `completed`，只有服务器确认才显示完成。HTTP 200 本身不代表完成；未确认、失效登录态或限速会显示错误。停止会中断后续请求，已被后端接收的记录不会撤销。切换账号会停止当前视频任务。

该功能基于当前学堂在线普通点播视频接口实现，平台规则变化时可能无法完成；暂不支持直播、回放或数字人视频。无需 Chrome/CDP，已完成的视频不重复上报。

## 图文标记看完

在「图文进度」选择课程，点击「一键标记本课程全部图文」。功能仅遍历该课程的图文单元（`leaf_type=3`），包含 PDF 附件所在的图文学习单元；已完成项自动跳过，未完成项默认 3 并发标记，随后读取详情确认 `finish=true`。也可先点击「查看图文进度」。

调用方式与平台「标记看完」按钮一致：`GET /api/v1/lms/learn/user_article_finish/<leaf_id>/?cid=<classroom_id>&sid=<sku_id>`。虽然使用 GET，该接口会修改进度；只有明确的 HTTP 429 会等待后重试，网络中断不会自动重放。HTTP 200 本身不视为完成，后端回查未确认的项会显示失败。可中途停止，重跑时跳过已完成图文。

## 讨论题批量完成

在「讨论题进度」选择课程，点击「一键完成本课程全部讨论（发1）」。发布内容固定为 `1`，范围仅为课程目录的讨论单元（`leaf_type=4`），不处理视频、图文下的普通评论区。已完成或当前账号已发表过的讨论不会重复发布；发布后会查询该学习单元进度，只有后端返回完成才计为成功。

任务默认 3 并发，可停止；HTTP 429 等待后重试，其他不确定的发布错误不自动重发。本地 `data/discussion-state/` 按课程和账号保存发布记录，以便中断后核对并避免重复评论。若发布成功但平台尚未计入进度，会显示未完成项，保留记录供后续回查。

## 课程答案库（JSON Demo）

连接登录态后，在「课程答案库」中选择一门课程，点击「获取本课程已公开答案」。需要获取未做题的答案时，勾选「提交未做题后采集答案」，再点击「提交并采集本课程答案」。这一模式会提交测试选项或占位内容，消耗作答机会并可能影响成绩；已作答题不会重复提交。采集默认同时处理 3 套练习，每套练习内按题顺序采集，支持停止。

题目列表中的 `user.answer` / `user.answers`，以及提交响应中的 `data.answer` / `data.answers`，在 `is_show_answer=true` 时作为标准答案来源。`my_answer` 只是账号的作答，绝不当作标准答案。单选、多选、判断和填空可采集；其他题型可保存平台公开的参考答案，但暂不自动提交。未公开、受限或无法识别的题目会标为缺失，不会用猜测补齐。

数据库保存在 `data/answer-db/<班级ID>.json`，无需 SQL 或额外数据库服务。每道题处理后原子写入，保留题干 HTML、选项、题型、标准答案、来源和采集状态。重跑时保留题目版本相同的已采集答案；提交结果不确定时先记录待核对状态，避免重复消耗作答机会。界面可查看已有答案、缺失项并下载 JSON。

```json
{
  "version": 1,
  "course": { "classroomId": 123, "title": "示例课程" },
  "exercises": {
    "456": {
      "section": "第一章测试",
      "leaf_id": 456,
      "exercise_id": 789,
      "questions": [
        { "problem_id": 101, "type": "choice", "answer": "B", "answer_status": "captured", "source": "submission_response" },
        { "problem_id": 102, "type": "judge", "answer_status": "missing", "error": "后端尚未公开标准答案" }
      ]
    }
  }
}
```

已采集的客观题使用与现有刷题函数兼容的 `type`、`answer` / `answers` 字段；缺失项带有 `error`，不能当作可提交的正确答案。本地数据库、Cookie 和抓包数据不会加入 Git。

## 任务并发与故障处理

视频、图文、讨论、答案采集和答题任务可以同时运行，各任务默认 3 并发，可在对应面板选 1–3；停止只影响当前任务。同类任务仍有重复启动保护，切换账号或断开会取消该账号的所有任务。本地 JSON 写入按顺序落盘，避免并发覆盖。

答题控制台需要选择课程，使用 `data/answer-db/<班级ID>.json` 的全部有效标准答案，按当前账号的学习单元详情获取班级、SKU、题集和课程标识。已做题跳过；查询失败不视为未做，不会继续盲目提交。旧版 `data/answers/` 文件不会再作为 Web 答题数据源。

所有任务共享 HTTPS 请求启动配速（至少 750 毫秒）。临时 TLS 握手失败、DNS 或连接中断仅在尚未建立连接或明确只读请求时重试 2 次；可能已收到的作答、评论和图文标记请求不自动重放。HTTP 403 表示平台拒绝访问，不是任务互斥；面板显示失败单元及停止原因，403 不自动重试。持续网络或平台访问限制仍需恢复后重跑。

## ⚙️ 配置（`.env`）

| 字段 | 说明 |
|------|------|
| `CLASSROOM_ID` / `SKU_ID` / `SIGN` | 课程标识，从学习页 URL（`.../learn/space/<SIGN>/<SIGN>/<CLASSROOM_ID>/...`）获取 |
| `CONCURRENCY` | CLI 旧配置兼容项；各面板和批量任务默认 `3`，可选 `1–3` |
| `COOKIE` | 登录态 |

> **关于限速**：提交接口约有 **20 次/分钟/账号** 的窗口限速，超出会被 `throttled`。本工具默认配速到约 20/分钟，平稳不触发；调小 `SUBMIT_INTERVAL_MS` 会更快但易撞限速。

## 📝 答案数据格式

把每套作业的答案放到 `data/answers/<作业名>.json`，由你自行准备：

```json
{
  "section": "1.1.2 小节测试",
  "leaf_id": 12345678,
  "exercise_id": 1234567,
  "questions": [
    { "problem_id": 11111111, "type": "choice", "answer": "B" },
    { "problem_id": 22222222, "type": "judge",  "answer": "正确" },
    { "problem_id": 33333333, "type": "multi",  "answers": ["A", "C"] },
    { "problem_id": 44444444, "type": "fill",   "answers": ["答案1", "答案2"] }
  ]
}
```

- `type`：`choice`(单选) / `multi`(多选) / `judge`(判断) / `fill`(填空)
- `answer`：单选/判断的答案；`answers`：多选/填空的答案数组
- `leaf_id`、`exercise_id`、`problem_id`：题目在平台上的标识

## 📁 目录结构

```
workflow/
├── server/        # 后端：Express + SSE + 静态托管（仅监听 127.0.0.1）
├── web/           # 前端：Vue 3 + Vite（玻璃拟态控制台）
├── src/           # 核心：纯 HTTPS 请求 / 题型解析 / 提交逻辑

├── data/answers/  # 答案数据（自行准备，不入库）

```

## 🛠️ CLI（可选，无需网页）

```bash
npm run check     # 验证 cookie 是否有效
npm run submit -- '<课程学习页URL>' --concurrency=3  # 从该课程答案库提交未做题
npm run verify -- '<课程学习页URL>'                 # 查该课程习题的服务器状态
npm run video -- '<课程学习页URL>' --course        # 扫描指定已选课程的全部视频
npm run video -- '<课程学习页URL>' --course --complete  # 一次运行，自动完成这门课的全部视频
npm run video -- '<课程学习页URL>' --course --complete --concurrency=2  # 视频级并发，范围 1–3
npm run video -- '<视频学习页URL>'                 # 只查询，使用 .env 的 COOKIE
npm run video -- '<视频学习页URL>' --complete      # 完成并回查
npm run video -- '<视频学习页URL>' --complete --duration=694  # 无法自动获取时补充时长
npm run collect-answers -- '<课程学习页URL>'       # 只读取公开答案，保存为 JSON
npm run collect-answers -- '<课程学习页URL>' --submit-unanswered  # 默认3套练习并发采集标准答案
npm run article -- '<课程或图文学习页URL>'           # 查询该课程全部图文进度
npm run article -- '<课程或图文学习页URL>' --complete  # 默认3并发标记该课程全部图文
npm run discussion -- '<课程或讨论学习页URL>'       # 查看该课程的全部讨论题进度
npm run discussion -- '<课程或讨论学习页URL>' --complete  # 给未完成讨论逐条发布“1”并回查
npm test          # 核心视频流程和任务状态测试（不访问真实账号）
```
