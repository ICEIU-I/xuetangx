# ICEIU · 学堂在线学习控制台

一个 Web 控制台，根据你提供的答案自动提交学堂在线（xuetangx.com）的小节/章节测试。
也支持查询与完成指定视频的观看进度，并回查服务器确认结果。
纯https协议实现。

## ✨ 功能

- 🔐 **微信扫码连接学堂在线**：扫码后由服务端获取并加密保存平台 Cookie，也支持粘贴 Cookie 兼容连接。
- 📊 **作业状态板**：一览所有作业的完成 / 判对情况。
- ⚡ **一键自动提交**：自动跳过已做的题，配速提交，避开服务器限速。
- 📜 **实时日志**：每道题提交结果逐行滚动，进度条 + 实时速率。
- 🎬 **整门课程视频**：选择一门已选课程，自动遍历该课程全部视频，跳过已完成项，批量上报并逐项回查；支持停止和重新运行。
- 📚 **课程答案库 Demo**：自动发现指定课程的作业、章节测试等练习，按题保存标准答案到本地 JSON，支持查看、下载和断点续采。
- 📄 **图文标记看完**：选择一门课程，一键标记全部图文（默认 3 并发），跳过已完成项并逐项回查。
- 💬 **讨论题批量完成**：在选定课程的未完成讨论单元逐条发布“1”，核对进度，并避免重复发帖。

## 🚀 快速开始

```bash
npm install
npm run console
```

打开 **http://127.0.0.1:8788**，在正式账号面板点击「微信扫码登录学堂在线」并用微信确认；服务端确认平台身份后会加密保存 Cookie。也可以继续粘贴已有 Cookie。连接后选择课程并点击「一键完成」。视频、图文、讨论各默认 3 并发；题库里有匹配答案的题立即开始作答。原来的单项入口收在「高级操作」中，与一键任务共用调度器，不会为相同课程重复启动同一模块。

微信扫码协议和失败处理见 [docs/wechat-platform-login.md](docs/wechat-platform-login.md)。

缺少答案时，在页面连接一个不同的测试账号。测试账号需由你手动加入同一课程班级；账号未提供或未选课时，其他模块继续。测试账号采集答案后先保存到本地 JSON，再立即交给正式账号答题。测试账号只用于采集，正式账号只使用已验证的标准答案。

## 多进程与限流

一个主进程负责 Cookie、请求发送、服务端限流响应和 JSON 写入；四个执行子进程分别处理视频、图文、讨论、答题，缺题库时按需增加采集子进程。子进程通过 IPC 请求主进程操作，不接收 Cookie，也不直接访问平台。

本地不再预设「每账号 20 次／60 秒」提交额度，也不记录或持久化提交计数。按任务默认 3 并发执行，主调度器不再添加固定 750 毫秒的请求间隔；每账号仍最多 3 个答题提交同时在途。

Go 服务收到 HTTP 403 后，该账号的请求从 60 秒开始指数退避，单次本地退避最多 30 分钟；如果平台提供 `Retry-After` 或更长的等待秒数则继续服从。403 会持续退避重试，直到平台恢复、任务被用户暂停/停止或账号失效，不因旧的重试次数上限提前把课程置为部分完成。HTTP 429 或其他限流响应优先使用服务端明确提供的等待值；明确拒绝的请求没有次数上限，使用 1–60 秒指数退避继续重试。只读查询遇到临时网络错误或 5xx 也会持续退避。视频心跳和图文完成写入的结果不确定时，先回查平台进度，确认未完成后再补传。另一账号和其他可执行请求继续运行。不主动探测或绕过服务端限制。

界面展示账号是否可提交，以及实际触发服务端限流后的重试倒计时；移除本地「已用／20」额度和按固定周期计算的时间估计。限流等待只存在于当前主进程内存，旧额度 JSON 不再读取或写入。任务、答案与防重复提交记录仍照常保存。

## 题库与恢复

题库继续保存在 `data/answer-db/<班级ID>.json`，兼容旧版 JSON。通过课程、题集、题目 ID、题型、题干、选项与版本指纹匹配答案；变化或缺失的答案只由测试账号补采。标准答案取自后端公开的 `answer` / `answers`，不将 `my_answer` 当作正确答案。

测试账号 Cookie 仅在主进程内存中，重启后需重新提供。任务快照和不确定写请求记录位于 `data/workflow/`，不含 Cookie。点击「暂停」保留进度，「继续 / 重试未完成项」先回查再执行；子进程异常退出只恢复对应模块，Node 旧服务重启后任务保持暂停，重新连接账号后继续。Go 服务使用 PostgreSQL 保存任务和加密凭据，服务重启后自动回查并继续原本运行中的任务，用户主动暂停或停止的任务保持原状。Go 服务也会自动恢复同账号、同课程最新一条因旧版 403 终止或视频/图文不确定记录而中断的任务；更早历史任务不自动重跑。正式账号失效暂停正式任务；测试账号失效只影响采集。完成计数和进度条只统计已确认完成及正确跳过的项目，等待重试和失败项不计为完成。

讨论内容固定为 `1`，仅发布到课程目录中的讨论单元；已完成或已发表的单元不重复发帖。网络中断导致结果不确定时先回查，不盲目重发。未公开答案、题目版本不匹配、未开放单元及已答错的题会单独显示，不能被当作全部成功。

## CLI：同样经过主调度器

先启动 `npm run serve`。CLI 复用控制台已经连接的账号，也可通过环境变量 `COOKIE` 和可选的 `TEST_COOKIE` 向本地主进程提供凭据；不要把 Cookie 写进命令参数或提交到 Git。CLI 不再直接访问学堂在线接口。

```bash
npm run complete-course -- '<课程学习页URL>'
npm run complete-course -- '<课程学习页URL>' --concurrency=3
npm run video -- '<课程学习页URL>' --course --complete
npm run article -- '<课程学习页URL>' --complete
npm run discussion -- '<课程学习页URL>' --complete
npm run submit -- '<课程学习页URL>'
npm run collect-answers -- '<课程学习页URL>' --submit-unanswered
npm run verify -- '<课程学习页URL>'
```

`collect-answers` 不加 `--submit-unanswered` 时只保存正式账号已公开答案，不进行采集提交。加该参数时需要测试账号。CLI 遇到等待账号/选课状态会提示后退出，任务保留在网页中；Ctrl-C 会暂停任务。每个本地工作目录仅允许一个主调度进程。

并发执行仍受平台自身的限流规则约束。持续 403 会保持任务等待并按冷却重试；账号失效或不支持的题型会如实报告。

## ⚙️ 配置（`.env`）

| 字段 | 说明 |
|------|------|
| `CLASSROOM_ID` / `SKU_ID` / `SIGN` | 课程标识，从学习页 URL（`.../learn/space/<SIGN>/<SIGN>/<CLASSROOM_ID>/...`）获取 |
| `CONCURRENCY` | 旧配置兼容项；一键任务使用面板或 `--concurrency` 参数，默认 `3` |
| `COOKIE` | 登录态 |

> 并发数只控制同时执行的数量。统一流程不使用 `SUBMIT_INTERVAL_MS` 等旧配置主动配速，收到服务端限流后再等待重试。
