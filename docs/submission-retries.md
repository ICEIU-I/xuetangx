# 答题失败后的自动恢复

正式答题和测试账号采集共用提交恢复模块，所有提交和回查仍通过主进程请求网关。

- 网络超时、连接中断和 HTTP 5xx：分别等待 1、2、4 秒后回查同一道题。任一次查询确认已作答，就采用平台结果，不重复提交，包括已作答但判错的题。
- 三次查询都明确返回同一版本题目的 `my_count=0`，才自动重新提交；每题最多额外重试两次。题目缺失、版本变化、作答次数字段缺失或回查失败，都保留待核对状态，不把它们当成未作答。
- TLS 建连前失败：确认请求未发出后，等待 1、2 秒有限重试。暂停、停止和账号失效会中断等待与后续提交。
- 平台明确的权限、作答机会或其他业务拒绝不会按网络故障重试。实际限流仍交给共享网关等待，不增加新的限流规则。
- 重试次数随提交记录落盘，进程重启和继续任务不会重置自动重试次数。旧的 `unknown` / `pending` 记录也会重新核对，确认未作答后可以恢复。超过自动重试上限仍标记失败；后续回查若确认平台已接收，会更新为已作答。
- 本轮最后回查若发现此前失败的题其实已提交正确，会修正成功/失败统计，清除该题的过时报错。

统一日志会显示“回查平台作答状态”“自动重试 1/2”等过程。平台未提供提交幂等键；多次回查能减少重复提交，但不能保证消除平台长时间延迟入账的竞争条件。
